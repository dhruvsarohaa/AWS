# R4 root integration manifest

All implementation files are R4-owned new files; existing shared files are root-owned.

1. Add `r4: r4Capabilities()` from `api/r4-integrations.mjs` to server `/api/config` capabilities. Default external capabilities are false and `localJourneys` is true. No environment flag can activate a missing adapter.
2. Before the generic workspace handler, route paths beginning `/api/workspace/integrations/` through existing `membership(event, store)` and `r4Route(method, path, requestBody(event), member, store)`. Exact routes: `status`, `explanations`, `routes`, `wearables`, `pollen`, `dense-air`. Use existing private no-store headers and session/revocation guarded client transport if later adding an enabled assistant panel.
3. `POST explanations` accepts `{snapshotId, activityId, language: 'en'|'hi', explicitUse:true}` only. Default returns the existing deterministic-guidance fallback because no trusted resolver/model is installed. A future adapter needs `options.resolveAssessment(reference, trustedMember)` returning `{assessment,sources}` and `options.adapters.explanation`; resolution must bind an actual frozen/current snapshot and activity server-side. It must never accept a client-provided assessment as trusted evidence.
4. Lazy-import default `R4JourneyPanel` from `src/components/R4JourneyPanel.tsx`. It takes `{language}`. Render only while History is active and its explicit local-journey entry is open. The panel stops tracking on unmount/hidden page; no sign-in is necessary for local travel records.
5. The existing global local-data clear handler must await `clearLocalJourneys()` from `src/lib/r4-journey-store.ts` along with clearing existing planning data. Report a clear failure rather than claiming all private data was removed. This helper also invalidates active position/import callbacks and notifies other tabs. Its revision tombstone contains no journey positions.
6. Do not add disabled empty route/pollen/hotspot/wearable panels, provider secrets, workers or deployment resources. Existing F17 guidance remains the usable explanation fallback. No provider/platform is selected by this implementation.

Targeted command: `node --test tests/r4.test.mjs tests/r4-storage.test.mjs` (24 checks). Re-run TypeScript, formatting, full suite and rendered journey QA after common-file integration.
