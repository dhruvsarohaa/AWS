## Working experience

- **Today / Plan / Evidence / History / Settings** are separate task views. The common place, date and language bar remains available across views. Hash navigation supports Back/Forward and activity/record links; the bounded plan date is in the URL. Coordinates and decision reasons are not placed in links. Navigation alone retains mounted forms and filters. Changing place/date intentionally resets the quick planner and alternative preview; open editor drafts remain separate from background evidence refreshes.
- **Today** leads with a next activity, outstanding review count, recorded/recheck state, evidence mode, forecast retrieval time and a direct action. A failed latest forecast retrieval remains visible even when earlier data exists.
- **First use** has a place → activity → rule progress guide. The quick planner separates activity/duration/allowed hours from rule acknowledgement, with Back. Local planning requires no login. Templates include school, walk, outdoor work and commute times; the latter does not rank routes.
- **Comparison** shows an original window and up to three feasible alternatives, duration, peak, overlap-weighted mean, coverage, allowed range and source retrieval time. Both original and alternative inputs must be complete; the forecast must be recent. Searches support 15–240 minute activities. Missing, stale and unsupported comparisons explain the reason instead of inventing options.
- **Preview** highlights the proposed band and outlines the original band on an independent chart. Selecting or cancelling a preview performs no repository write. Continue opens the existing decision editor; recording requires a reason and freezes the reviewed evidence. A refresh can update a preview before the editor opens; the source timestamp remains visible.
- **Plan editing** keeps name, location and activity times visible; repeat days/flexibility/indoor option/intensity are disclosed together. Repeat days and permitted times are summarized when collapsed. Validation opens the relevant disclosure before focusing the invalid field. Save failures retain the draft; cancel offers explicit discard when needed.
- **Evidence** keeps station observations separate from the regional model. PM2.5/PM10/both chart focus retains the PM2.5 planning rule and hourly table. PM10-only view does not draw the PM2.5 rule against PM10. R2 adds a separate validated six-pollutant model panel; no official Indian AQI is inferred.
- **Stations** have selectable observation entries with time, distance, source, units and freshness. A native dialog shows period, quality, owner/provider and retrieval details; Escape/close and browser Back close it. The selected reading is frozen while the drawer is open. R2 expands the list to the bounded returned nearby readings and adds an optional map; this is not a complete national catalog. Retrieval metadata is frozen with the selected observation.
- **History** can open the particular record from an activity, with date/place/activity filters, frozen original/chosen evidence, report and summary. Summary language follows the global preference. Missing linked IDs are explicit; another record is not substituted. Print-only output is enabled only for the active History view, avoiding a hidden report being printed from another screen. CSV retains stable English column names and formula neutralization.
- **Settings** combines location, validated backup import/export, storage recovery export, privacy explanations, optional workspace and searchable bilingual help. Local deletion requires typing `CLEAR` and a durable reset before owned legacy keys/location are removed. It signs out locally; shared workspace records and server evidence are not deleted. Partial cleanup failures are explicit.
- **Recovery export** reads the stored planning document and owned legacy bytes without normalizing or replacing damaged content. It differs from the validated planning backup and is for recovery/inspection. This does not provide automatic repair of corrupt IndexedDB. If durable storage is unavailable, the delete flow refuses to claim successful stored deletion.
- **Responsive CSS** adds a mobile bottom navigation with safe-area padding, single-column comparison/template cards and a full-height station drawer. Inputs/actions have at least 44px targets, data states use text, and navigation has `aria-current`. These are source-level provisions, not a completed accessibility or device audit.

## Checks and release boundary

- `pnpm build` and `pnpm lint` pass for this bundle; the final command outcomes are recorded in chat. No new automated tests were added or run. The previous 120-check baseline is not verification of this UX bundle.
- Local browser automation was previously rejected by saved app permissions. It was not retried or bypassed. **Rendered layouts, keyboard/Back/modal behavior, printing and destructive settings flows remain unverified.**
- No credentials were read, provider keys changed, cloud resources provisioned or new external integration enabled. Existing API contracts and AWS architecture remain the foundation.
- The existing development process remains separate from production deployment. A running UI does not establish live provider availability; failed refreshes preserve timestamps and unavailable states.

### Manual browser review before release

1. Navigate all five views, Back/Forward and a direct record link; preserve place/date; keep quick fields/history filters when only switching views. Check unavailable linked records without substituting a different record.
2. Use keyboard only: skip link, navigation, plan advanced-field validation, alternative preview/Continue, station drawer Escape/Back and dialog discard/save failure. Check focus restoration and no background focus while modal.
3. Review 320px/390px layouts, landscape, 200% zoom, large text and screen-reader labels. Check navigation safe area, chart selector/table and dropdown visibility.
4. Compare complete/partial/zero-valued/stale data, original/proposed overlapping bands and PM10-only focus. Confirm incomplete originals cannot be presented as a complete lower-peak comparison.
5. Record a choice, open its historical report and export/print. Navigate away, then print the other view: the private History report must not be substituted. Review CSV/summary private fields.
6. Use disposable browser storage to exercise import, storage denial, conflicting tabs, stored recovery export and confirmed local deletion. Corrupt storage must remain untouched when the durable reset fails; shared/server records must remain unaffected.
7. Review Hindi form/errors/disclosures with a fluent speaker; expand remaining untranslated legacy/workspace text before promising complete localization.
