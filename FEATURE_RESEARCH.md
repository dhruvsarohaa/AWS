# Airday feature research and selection

Reviewed: **8 October 2026, India Standard Time**.

Purpose: identify useful feature patterns from the four requested products and assess a working Airday implementation. These are proposals for selection, not newly implemented application features. Public product pages/documentation were reviewed; vendor accounts, devices and authenticated data feeds were not tested. Marketing claims are not independent evidence of accuracy.

The complete extension roadmap is in [FEATURE_IMPLEMENTATION_MAP.md](FEATURE_IMPLEMENTATION_MAP.md): all 32 features, release phases, dependencies, file/API/storage changes, acceptance criteria and external setup gates.

The public-site frontend/experience comparison is in [FRONTEND_UX_RESEARCH.md](FRONTEND_UX_RESEARCH.md), covering 36 missing or partial UX improvements and the proposed Airday screen/component structure.

## What "real time" means here

- The page can update whenever new evidence arrives. It cannot create a new measurement by refreshing more often.
- The existing pilot schedules approximately hourly model retrieval and 15-minute observation retrieval, with provider budgets and timestamps. Provider observations may arrive later.
- Open-Meteo documents CAMS Global air data at roughly **45 km**, with **3-hour source steps** and model updates every **12 hours**. Hourly API values do not establish street or building precision. It supplies additional gases; its pollen fields are Europe-only. [Air Quality API documentation](https://open-meteo.com/en/docs/air-quality-api)
- Open-Meteo's hosted free service supports non-commercial use and has quotas/no uptime guarantee. A commercial launch needs the appropriate access/licensing arrangement. [Pricing and terms](https://open-meteo.com/en/pricing)
- Station-based features require actual, suitably recent observations at that location. Forecast-only operation remains available when observations are absent.
- Historical features show retained evidence and compatible history actually retrieved. No invented earlier months or years.

**Route dependency finding:** Ambee's current air-data page lists **5 km** spatial resolution, finer than 1 km **upon request**, hourly present-condition refresh and daily forecast refresh. Access at a finer resolution is not guaranteed by the Clean Routing marketing page. Its pricing is organized around operational requirements; no ongoing free Clean Routing entitlement was verified. Obtain suitable Indian coverage/sample access and a quote before depending on it. [Ambee Air Quality data](https://www.getambee.com/api/air-quality), [Ambee pricing](https://www.getambee.com/pricing)

A routing engine such as [openrouteservice](https://openrouteservice.org/services/) can supply travel paths; it does not supply pollution truth. Account quotas and current production API base URL must be checked against [current API documentation](https://openrouteservice.org/dev/) before integration. Its provider announced migration from the older API domain; copying older tutorials can lead to quota/access failures. [Provider migration explanation](https://ask.openrouteservice.org/t/quota-exceeded-on-directions-while-dashboard-shows-full-quota-standard-key/8068)

**Device dependency finding:** Home Assistant exposes authenticated entity reads and service calls that can bridge supported devices. Merely posting an entity state does not command the physical device; use its service call interface and confirm actual state. Hardware compatibility remains device-specific. [Home Assistant REST documentation](https://developers.home-assistant.io/docs/api/rest/)

**Tracking dependency finding:** Browser geolocation requires permission and a secure context. Native Android also restricts background location and requires appropriate permissions/services. An installable web app alone does not establish reliable all-day journey tracking. [Browser geolocation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API), [Android background location](https://developer.android.com/develop/sensors-and-location/location/background)

AirTrack describes its exposure score as an estimate rather than a measurement of every breath. A new Airday indicator would need a published calculation, explicit assumptions and validation; do not copy a proprietary score or convert it into a health diagnosis. [AirTrack scoring explanation](https://www.airawarelabs.com/article/airtrack-scoring-overview)

## Recommended selection

For the strongest working two-day extension, prioritize a complete decision flow:

1. **F02 — activity timeline:** show which reviews are unresolved and which action was recorded, with original/chosen evidence.
2. **F01 — quick best-time finder:** let a walker, worker or school staff member plan an activity without filling an entire timetable.
3. **F05 — relevant in-app alerts:** direct users back to the affected activity when evidence changes.
4. **F03 — station map:** expose actual returned coverage; keep model and observations separate.
5. **F08 — printable/CSV report:** make the chosen action reviewable and shareable.

This is a ranked menu, not a promise to finish all five in two days. F02 and F01 are the central demo; add supporting features only after the flow and deployment work. F23 weather and F24 fires are useful later context additions. F29 purifier control can become a separate hardware pilot. F25 cleaner routing requires a real data trial before committing to it.

Existing audit work on keyboard access, recovery, histories and shared proposals should be incorporated into these flows. Adding feature tiles while the underlying action cannot be completed would weaken usability and execution.

### Judge-facing demonstration

An individual or school staff member chooses location and activity duration → sees labeled regional forecast and real available station evidence → compares permitted times → records the decision and reason → receives a changed-evidence prompt → exports the dated action record. The AWS deployment serves evidence, queues ingestion and stores optional shared audit records.

Measure successful reviews/recorded choices and user-reported follow-through. A model comparison does not establish a measured pollution-dose reduction, improved health or cleaner city air.

## Selection and release boundaries

- Website feature descriptions do not grant access to vendor APIs or datasets. No undocumented Airveda/Oizom/Ambee endpoints or permanent free keys are assumed.
- AWS credits are an infrastructure budget; third-party data licensing, vendor hardware and telecom charges need their own budget.
- The existing architecture is a bounded pilot with capped active areas/stations. Adding favorites/maps must preserve admission, caching and upstream quotas before expansion.
- No current India-wide fresh-monitor coverage, finer-grid accuracy, continuous tracking or device-control claim is justified by these public pages alone.
- Application features remain unchanged by this research and the implementation map. The proposed first bundle is the activity timeline and quick best-time finder, followed by review alerts and dated reports; implement and verify each flow end to end before extending the release.
