## Delivery and retention

Scheduled email is opt-in and never uses sample/replay evidence. The account email comes from trusted, administrator-synchronized membership; this release does not accept arbitrary alternate destinations. Re-run membership provisioning after Cognito email verification or changes. Private journal reasons are not included in scheduled alerts/briefs; the separate existing approval email includes the organization's approved reason.

Workers persist an unknown delivery state before calling SES. SES acceptance sets **accepted**; only matching provider feedback sets **delivered**. Bounce/complaint feedback suppresses the destination. Feedback is bound to the message ID, tagged record/owner, configuration set/account and hashed destination, and retries contended updates. Unknown outcomes are not automatically resent. An opt-out observed before the final send check prevents the send; SES cannot recall a message already submitted.

The template includes an SES configuration set, delivery/bounce/complaint/reject/rendering-failure events, a feedback Lambda, dedicated encrypted feedback dead-letter queue, scoped EventBridge queue policy, Lambda failure destination and queue alarm. No open/click tracking is configured. EventBridge target delivery failures and Lambda processing failures need separate recovery, as described in [AWS's dead-letter queue guidance](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-rule-dlq.html) and [SAM EventBridgeRule documentation](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/sam-property-function-eventbridgerule.html).

Disable, unsubscribe and membership revocation remove the synced plan/area from the active subscription, rotate its generation, stop due evaluation and free pilot admission. Outbox receipts expire after 30 days; due-outbox references expire after two days. DynamoDB TTL deletion is asynchronous. Private workspace owner references support explicit workspace erasure even after membership transfer; erasure preserves another workspace's subscription/receipts. The operator's `revoke` and `erase-workspace` paths include R3 email cleanup. Audit records, Cognito identities and retained backups follow the documented organization retention process. Global bounce suppression remains until an operator investigates it.

File storage waits for pending durable writes before returning reads. An uncertain durable failure blocks further reads/mutations until recovery; it cannot present uncommitted local state as saved. DynamoDB transactions use conditional writes, with no table scans in the runtime subscription scheduler.

## Configuration and pilot limits

All optional R3 integration flags default off. No deployment, SES send or live provider test was performed during this implementation.

| Integration               | Enable after external verification                                                                                 | Server-only configuration                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared workspace/groups   | Deploy Cognito/DynamoDB and provision isolated organization members/roles                                          | Existing Cognito and workspace settings                                                                                                              |
| Scheduled email           | `REVIEW_EMAIL_ENABLED=true` plus verified SES sender/destinations and tested feedback                              | `NOTIFICATION_SENDER`; random `ALERT_SIGNING_KEY` of at least 32 characters in the provider secret; `SES_CONFIGURATION_SET` supplied by the template |
| Public display/API/widget | Both `PUBLIC_EVIDENCE_ENABLED=true` and `PUBLIC_REDISTRIBUTION_REVIEWED=true`, after source redistribution review  | Optional `PUBLIC_EMBED_ORIGINS`, comma-separated exact HTTPS origins, without paths or wildcards                                                     |
| Weather                   | `WEATHER_ENABLED=true`, after Open-Meteo access/terms/coverage review                                              | Existing optional `OPEN_METEO_API_KEY`; the separate customer weather endpoint is used when present                                                  |
| Satellite fires           | Both `FIRES_ENABLED=true` and `FIRMS_PRODUCT_VERIFIED=true`, after authenticating and validating the selected feed | `FIRMS_MAP_KEY`; `FIRMS_PRODUCT=VIIRS_NOAA20_NRT` or `VIIRS_NOAA21_NRT`                                                                              |

`.env.example`, `scripts/preflight.mjs`, `scripts/deploy-aws.ps1` and `template.yaml` include these settings. Secret values never become stack parameters or frontend `VITE_*` variables. The deploy script checks explicit email/fire/public gates before provisioning. Local job processing records local-only/not-configured delivery and never calls SES.

Context jobs use admitted air areas rather than a second unbounded location registry. Successful context refreshes have a one-hour minimum interval; failures retry after five minutes while retaining original evidence timestamps. Hard request budgets include retries: weather **5/minute, 30/hour, 500/day**; FIRMS **2/minute, 20/hour, 100/day**. These ceilings can defer refreshes before every admitted area is refreshed; the UI exposes retained age/failure. Public evidence does not create private subscriptions or bypass area admission. Scaling these bounds needs measured load, provider capacity and cost review.

Weather follows the [Open-Meteo weather contract](https://open-meteo.com/en/docs). Fire ingestion follows the [NASA FIRMS area API](https://firms.modaps.eosdis.nasa.gov/api/area/). Provider redistribution/commercial access and NOAA product authenticity are external gates; flags do not establish that a review occurred.

## Verification and remaining release checks

R3 adds **44 focused offline tests**, plus two membership-revocation/session regressions in the authentication suite. They cover record retries/reopening/replacement, one-off and chosen-window approval, tenant/role/version conflicts, atomic failure/recovery, group bounds, explicit consent, subscription admission, quiet hours, transitions, late rescheduling, opt-out/revocation/erasure, queue/evaluation failures, SES uncertainty/feedback, nested public/workspace contracts, escaping/frame origins, and provider time/unit/product/retention rules. Fixtures are synthetic and excluded from production.

The final recorded results are in RELEASE_STATUS.md. TypeScript/production frontend and API builds, lint, infrastructure/configuration/security checks and SAM validation are local evidence, not a cloud or browser usability certificate.

Before enabling a real pilot, verify:

1. Deployed Cognito sign-in, two organizations, role revocation, chosen-window approval and save/refresh recovery under real DynamoDB concurrency.
2. Actual SES sandbox/production authorization, accepted-versus-delivered feedback, bounce/complaint suppression, quiet hours, opt-out races and both feedback failure paths. Replay feedback into its handler, never into the notification queue; never blindly resend unknown deliveries.
3. Public source rights, widget frame allowlist, production CORS/CSP and phone/keyboard/high-zoom public display behavior. Source numerical provenance remains independent of organization decisions.
4. Authenticated FIRMS NOAA product coverage/acquisition/confidence and real weather fields/units/coverage. Test outages without replacing retained timestamps or air evidence.
5. A measured pilot load/cost and cloud restore/retention drill before increasing limits or making reliability claims.
6. Physical-device, screen-reader/high-zoom/full-keyboard accessibility and install/offline/reconnect checks. Local R3 desktop/390-pixel rendering and Hindi context-label smoke checks are recorded in R3_BROWSER_REVIEW.md. Advanced workspace/email/public integration controls currently use English.

R4/R5 features, routes, wearables, pollen and physical equipment control are outside this implementation.
