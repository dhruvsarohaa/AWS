Initial review 10 October 2026; repaired application rechecked just after midnight IST on **11 October 2026**. These are real provider responses, not synthetic fixtures. Values describe the named station at its original measurement time; they are neither official Indian AQI nor measurements at a user's building.

## What was checked

- The running API on port 3001 was queried for New Delhi, Noida, Gurugram, Mumbai and Bengaluru between **18:14–18:16 UTC (23:44–23:46 IST)**. Each completed location returned 72 regional forecast points.
- A separate bounded diagnostic made **eight authenticated OpenAQ requests** at 18:17 UTC: five complete location catalogs and three Delhi latest lookups. It used the existing key internally without printing key values, headers, environment contents or raw errors.
- [Public diagnostic results](artifacts/live-provider-coverage.json) preserve all returned location metadata, plus the three actual PM2.5 latest responses. [Diagnostic script](scripts/probe-monitor-coverage.mjs) is reproducible and limited to eight provider requests per invocation. It does not update the application cache or call AWS.

Catalogs were centered on the application's rounded 0.1° ingestion coordinates and searched within 25 km. Their returned counts were Delhi 96, Noida 67, Gurugram 50, Mumbai 45 and Bengaluru 22. None of these five responses indicated pagination truncation. Counts include historical and non-reference installations; they do not establish fresh outdoor coverage.

## Defect found and repair implemented

The old registry chose the five closest stations to the rounded ingestion center before considering reporting recency. In Delhi those included an obsolete US-post location last reporting in 2016. The recent AirNow station above was **16th** in that distance ordering; Air Check was **13th**. The catalog already contained usable fresher candidates, but the application never requested their latest values.

The repair in `api/providers.mjs`:

1. Validates Indian stationary candidates, location/sensor IDs, coordinates, the 25 km radius and PM2.5 concentration units. Explicit indoor labels in station, locality or owner metadata are conservatively excluded. OpenAQ does not supply a documented field proving outdoor siting; absence of an indoor label is not proof.
2. Prioritizes valid recent catalog reporting, then provider reference-monitor metadata and distance. Older fallback candidates retain their actual times; future, impossible and unknown catalog times cannot be prioritized as current.
3. Still checks no more than **five stations' latest readings per area refresh**. Actual PM2.5 sensor times determine displayed freshness. No forecast value substitutes for a missing measurement and no readings are averaged together.
4. Versions the selection registry so legacy nearest-five caches are rediscovered. Rediscovery failure preserves old catalogs and measurements; the engine retains original source timestamps.
5. Preserves `referenceMonitor`, instrument labels and explicitly unverified siting in normalized provenance.

Station capacity now has validated `AIRDAY_MAX_ACTIVE_STATIONS` configuration: **20 by default locally, maximum 40**. The deployment template's bounded pilot setting is 40. Existing leases and evidence are retained; no cache eviction was used to make the check pass. With 40 stations, the allowance for latest, flags, normal history pages and area metadata, including two request attempts, is approximately 460 calls/hour and 11,040/day when paced. The independent minute/hour/day quota checks and worker deadline still apply to bursts, retries and backlogs.

`tests/openaq-selection.test.mjs` supplies 17 synthetic regression checks for selection, units, timestamps, indoor/mobile exclusion, legacy rediscovery, provenance, bounded capacity, admission contention, no eviction, request budgets and actual observation tie-breaks. Focused backend/evidence-status/selection checks must be run again after any subsequent provider changes. Synthetic checks prove those code paths, not the live measurements in the table.

## Remaining operating limits

- Many returned CPCB-style feeds stopped at 7 October during this check. The underlying upstream cause was not diagnosed. Other AirNow and AirGradient stations were reporting later; this is not evidence of a country-wide outage.
- Mumbai's admitted AirNow PM2.5 latest value was verified as recent. Bengaluru's admitted candidates did not establish a current usable outdoor PM2.5 measurement. No coverage claim is made from catalog timestamps alone.
- No data.gov.in key was connected in the running app, and its numerical adapter remains gated on verified quantity, units, averaging interval and timestamp semantics. Adding a key alone does not satisfy those gates.
- A regional forecast-only experience remains the honest fallback when admission, source, siting or measurement freshness is insufficient. A successful HTTP response or a recently fetched old reading is not fresh monitor coverage.
- This is a five-place snapshot and a bounded pilot, not nationwide station coverage, calibration validation, accuracy evaluation or an uptime guarantee. OpenAQ data attribution and per-source licensing still apply.

## Verified provider contract references

OpenAQ's [locations operation](https://docs.openaq.org/api/operations/locations_get_v3_locations_get) documents coordinates, a maximum 25 km radius, embedded sensor parameter metadata, `isMobile` and `isMonitor`. The [locations resource](https://docs.openaq.org/resources/locations) describes owner/provider and licensing metadata. The [latest resource](https://docs.openaq.org/resources/latest) documents `sensorsId` joining and original measurement time; latest polling does not reconstruct all out-of-order ingestions. [API key instructions](https://docs.openaq.org/using-the-api/api-key) require authentication, and [free limits](https://docs.openaq.org/using-the-api/rate-limits) are 60 requests/minute and 2,000/hour per key.
