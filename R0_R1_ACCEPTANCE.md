## Defects repaired during acceptance

- Migration no longer substitutes starter activities for a valid unconfigured plan, drops oversized legacy history or treats empty corrupt values as absent.
- Explicit recovery preserves damaged originals and replacement together, rejects changed-after-review content and does not silently replace unreadable evidence.
- Activity identity is validated across recurring and quick plans. Pending response selection is scoped to location/date/plan/record lifecycle.
- Wrong-location, malformed, missing or nonlive evidence is withheld from current planning. Final save rechecks freshness, scope and material changes, including an editor left open while its evidence expires.
- Stored reviewed activities contain the declared activity fields only; rerecording does not embed previous history recursively.
- Incomplete low windows no longer imply complete below-rule evidence. Stale/future/unknown or missing/partial retained evidence cannot resolve a current review merely because it stayed unchanged.
- Unchanged incomplete evidence can retain a manual outdoor/indoor/cancelled response as unresolved history. Rescheduling and shortening require a complete chosen window; material coverage/value changes and nonfresh retrievals still reject the frozen draft.
- Alerts render the current material transition/dismissal and do not let an unchanged dismissal suppress a new episode.
- Private labels/reasons require explicit export opt-in; coordinates are excluded. Original/chosen evidence and legacy gaps stay distinct in CSV, print and text summaries.
- Deterministic review reasons and guidance are bilingual; user-written reasons and provider text retain their original language. Guidance respects configured indoor availability and feasible model windows.
- Backup replacement uses an inline explicit confirmation instead of relying on a blocked native confirmation dialog; cancelling restores focus. Native time-field edits are handled consistently by the finder.
- Print no longer creates a blank second page from viewport minimum heights. Both new save-time freshness reasons have Hindi translations.

## Live evidence and remaining limits

The local live Delhi forecast returned HTTP 200 with **72 hourly points**. Authenticated OpenAQ retrieval returned **one reading dated 7 October**, which was stale; present-day station coverage is not established. A working key or returned station does not prove a current, representative measurement at a school or street.

Remaining gates:

- Broaden race/device lifecycle scenarios beyond the listed checks. Local production-origin HTTP/proxy health and live forecast smoke checks passed; complete deployed smoke checks after AWS provisioning.
- Verify R2's ten features, including production install/first-offline-launch/cache-aging/update/reconnect behavior. The injected R1 save failure above does not establish offline PWA acceptance.
- Verify current station/provider behavior and multiple Indian cities; review optional CPCB metadata before enabling numeric readings.
- Review other browsers, physical phones, high zoom/reflow and screen-reader usability. The checked dialogs, keyboard operations, Hindi flow and 390-pixel layout cover only the listed scenarios.
- Deploy and verify AWS HTTPS, data stores, secrets, network controls, operations and costs after local acceptance. No AWS resources were deployed in this review.

The original estimates remain **R1 3–5 days, R2 5–10 days, R1+R2 8–15 days and R0+R1+R2 10–19 days for one developer**. They are planning estimates, not elapsed-time measurements or proof that all release work finished in two days.
