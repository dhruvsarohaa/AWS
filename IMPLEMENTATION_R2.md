## Persistence and contracts

- Planning document **schema 2**, in the existing `airday-planning` IndexedDB store. A valid schema-1 document is upgraded in one transaction, its revision increments, and original bytes are retained under `planning-v1-recovery`. Other tabs receive the new revision. Old writers cannot overwrite schema 2. Unknown/damaged versions preserve their bytes and use existing recovery/session controls.
- Validated schema-1 and schema-2 backups are importable. Merge rejects conflicting IDs, overlapping activity history and capacity overflow; it never silently drops favorites/feedback to fit. Replacement remains explicit. Recovery export includes the migration copy.
- Public offline snapshots are separate from plans, feedback, auth and private workspaces. An allowlisted projection strips unexpected extensions at every public envelope, rounds selected coordinates and recomputes station distances. Read-time projection also protects older valid envelopes without silently rewriting stored originals. They are limited disposable evidence caches, not personal-history retention. Unknown/invalid bytes reject reads/writes; failed atomic saves preserve the earlier complete snapshot. A clear invalidates saves waiting on an older database opening.
- Dashboard **schema 2** stays compatible, with optional `forecast.pollutants` series envelopes at **schema 1**. Existing PM points remain the planning interface. Gas source/unit/timestamp arrays are validated before UI use. The public configuration response declares the supported dashboard/history/pollutant-series/local-planning contract versions.
- `GET /api/history` is public evidence only, **schema 1**. Inputs: existing `lat/lon/city/state/mode`, `kind=runs|forecast|observations`, `from`, `to`; `run` for forecast or `sensor` for observations; opaque `cursor` for the next page. Cursor scope binds area/kind/source/range. No arbitrary partition key is accepted.
- DynamoDB reads use partition/range `Query`, not table scans or bulk archive decompression. `RUN#area` pointers and `RUNS#area` timestamp catalogs link to immutable `FORECAST#id`; observations use existing `HISTORY#sensor` timestamp records. Local stores expose the same bounded range interface. Retention is 90 days; expired rows are excluded even before DynamoDB TTL deletion.
- Run indexing failures are separate from current forecast availability. Existing pre-R2 archives are not automatically turned into indexed historical trends; history grows with successful subsequent ingestion. First retrieval is not claimed to be model issuance.

## Maps, offline policy and release controls

- Pilot basemap: `https://tile.openstreetmap.org/{z}/{x}/{y}.png`. No key. Explicit user action sends browser IP and rounded viewed tiles to OSM; no raw GPS marker/request. Zoom is bounded and no tiles are prefetched, bulk downloaded or cached by our worker. Normal browser HTTP caching remains enabled. Attribution is visible; the Leaflet BSD license ships in `third-party-notices.txt`.
- `VITE_STATION_MAP_ENABLED=false` hides map controls. OSM public tiles have no SLA and are not a production capacity promise. Before broad rollout, choose/review an appropriate tile service and update its explicit CSP origin/configuration. The deploy script now allows only the reviewed tile host, self workers/manifest, and an origin-preserving referrer policy.
- The service worker caches only an allowlist of static files from the build, including required shared style dependencies. A validated planner date query can use the cached shell. API paths, authorization-bearing requests, other query-bearing URLs, external origins, map chunks/tiles and private responses are excluded. Public-display/unsubscribe navigation is not treated as the offline planner route. Map code remains lazy. Style/chunk sharing does not enable paused R3 features.
- `pnpm build` produces the static shell/worker and code-drawn PNG icons. **Vite development does not register a service worker.** Use a production build on HTTPS or loopback preview for installation/offline inspection. A first successful online visit is needed; install UX varies by browser.
- No live observations, historical gaps or provider failures are replaced with samples. No device commands, SMS, route ranking or official orders are introduced by R2.

Primary references reviewed: [Open-Meteo Air Quality API](https://open-meteo.com/en/docs/air-quality-api), [Leaflet stable download](https://leafletjs.com/download.html), [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/), [MDN service-worker lifecycle](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers), [MDN installability](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

### Defects repaired during acceptance

- Original-versus-chosen model display previously compared the effective chosen time with itself. It now uses the retained original window and states clearly that refreshed model values are separate from frozen history.
- Date/interval/source validation rejects normalized impossible dates, mismatched metadata, gaps and overlapping series; zero remains valid. Run-history retrieval preserves first retrieval, and reconciliation/retention/cursor bounds remain explicit.
- Recap no longer fills missing chosen times with original durations. Private recap projection excludes coordinates and nested mutable records; clear feedback refuses a document changed after review.
- Feedback uses complete bounded context, a synchronous double-submit guard and context-reset drafts. Imported feedback cannot point at an existing decision from another place/date/activity.
- Offline public projection strips unexpected private extensions. Read-time projection protects older envelopes; corrupt originals are preserved. Cache clearing invalidates outstanding old-generation writes.
- A missing shared CSS dependency blocked full shell pre-cache despite the online page working. Required shared styles now stay in the static manifest, while guarded optional dependencies and invalid private/navigation queries remain excluded. Browser dated offline reload passed after that repair.
- Native pagination QA fixtures now follow the production ISO#hash observation key format. The corrected fixture and a 501-record regression verified the 500-row first page and single-row next page without warnings.
- R2 form boundaries, input text, long-content wrapping, map target sizes and reduced-motion styles were upgraded; the existing design remains in place.
