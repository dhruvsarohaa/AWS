## Local journey privacy, recovery and bounds

The local journey entry is lazy and opens from History through an explicit action. Starting GPS is a separate action after an unchecked exact-position consent box. The location-selection button does not start tracking. Only this visible panel records; navigation, hiding the page, permission/reception loss, save failure or a bound interrupts recording. Returning does not resume GPS automatically. A browser suspension can interrupt the final write, so a retained recording is shown as recovery rather than claimed complete.

Journey storage is separate from planning backups: `airday-local-journeys`, IndexedDB schema 1, one optimistic revisioned document. Each save is an atomic transaction. A revision conflict preserves the draft and requires export/reload; failed or corrupt/unknown storage is not replaced with an empty collection. Export original storage for recovery or explicitly clear it. The global Airday clear action also calls `clearLocalJourneys()`. Clear invalidates active callbacks/imports and writes an empty revision tombstone, so an old tab cannot recreate private route records. Cross-tab changes are announced; old revisions cannot overwrite newer records.

Launch bounds: 10 saved journeys; 10,000 points per journey; 50,000 points total; GPX input at most 1 MB; imported dated points within 366 days; each dated journey at most 24 hours. Coordinates use WGS84 ranges. GPX import supports namespaced GPX 1.1 **tracks** only, preserves missing timestamps, rejects duplicate/reversed/future or invalid dates, and does not import routes/waypoints, external metadata, links, DTD, entity declarations, CDATA or arbitrary XML instructions. XML depth and token counts are bounded. Import is a preview followed by explicit local save; matching previously imported points are rejected as duplicates.

Foreground fixes are sampled at least five seconds apart. A current fix must provide finite coordinates, explicit time and accuracy no worse than 1,000 metres. Missing fixes do not create invented positions. Separate GPX segments, missing times and time gaps over two minutes stay disconnected. Distance and recorded minutes count only connected, dated spans; positional accuracy can limit their usefulness. Untimed points remain visible/exportable and do not acquire invented durations. These records do not measure physiology, health improvement, inhaled dose or a pollution benefit.

Exported GPX contains exact saved positions and explicit point times; its label is escaped. Point details display UTC and reported GPS accuracy. The default table lists travel summaries without showing exact positions. Export and all-journey deletion are deliberately labeled; full deletion has confirmation. Reload protects an unsaved draft with export/replace/keep choices. No route reaches shared/public projections, URLs or cloud requests. Removing an exported file from another application is outside local-data deletion.

## Explanation and comparison contracts

The explanation input is a server-computed minimal assessment: snapshot ID, rule version, evidence status/completeness, threshold and peak. It excludes precise location, personal reasons and child/student data. An optional model can rearrange exactly the required reviewed state/limits/indoor phrases and cite only a supplied source ID; arbitrary prose, new actions and changed evidence state are rejected. Per-account quota is 3 attempts/UTC day and global quota is 20, counting attempts including failures. Quota storage failure also falls back. Execution times out at at most five seconds and signals abort. Adapter transport, provider cost admission and current model/region rights must be established before activation.

Route comparison uses complete segment-time concentration integrals in `µg/m³ × hours`, separated from travel distance/duration. A ranking requires distinct resolving cells, a reviewed maximum resolution (at most 1 km), complete valid traversal intervals and non-overlapping integrated uncertainty bounds. This is a conservative pilot criterion, not an established universal accuracy threshold. Missing uncertainty is incomplete evidence. Offsets are normalized as instants. No unlike providers/statistics/units are averaged.

The wearable scope `activity:read` is an internal neutral contract. It is **not** asserted to be an actual scope on an unselected platform; a future selected adapter must map its documented narrow permission into this contract. This boundary imports no raw route, heart rate or health profile and performs no token exchange. Deduplication is bounded within a supplied batch; a selected platform importer must also persist source IDs across batches for idempotent sync and implement export/delete.

## Code and verification

- `api/r4-integrations.mjs`: capability gates, deterministic/assisted explanation contract, quota/fallback and private route boundary.
- `api/r4-contracts.mjs`: reviewed route, Indian pollen, evaluated-cell and wearable import normalization.
- `src/lib/r4-journeys.ts`: bounded GPX parser, journey validation, travel summaries and local GPX export.
- `src/lib/r4-journey-store.ts`: atomic local storage, recovery export, conflict and clear invalidation.
- `src/components/R4JourneyPanel.tsx`: accessible bilingual local journey flow.
- `tests/r4.test.mjs` and `tests/r4-storage.test.mjs`: **24 passing offline checks** covering malicious XML, gaps/null/zero, bounds, provenance, duplicates, unknown schemas/storage absence, foreground fixes, explanation redaction/citations/actions/quotas/timeouts and integration gates/coverage/uncertainty/revocation. A fault-injectable asynchronous transaction surface checks competing revisions, failed commit preservation, original corrupt-record export, explicit empty tombstones and clear during a pending write; this does not claim actual browser durability.

TypeScript checking passed after the initial implementation; root integration runs the final build, complete suite and browser checks and records those separately. No actual foreground GPS session, model/provider response, wearable OAuth session or field evaluation has been verified by these offline checks.

Primary format/API references reviewed on 10 October: [GPX 1.1 schema](https://www.topografix.com/GPX/1/1/) and [W3C Geolocation](https://www.w3.org/TR/geolocation/). GPX track segments are the source of explicit reception breaks; browser geolocation is permission-bound and does not establish reliable background tracking.
